## 1. 系统概览

### 1.1 能做什么

| 功能 | 看板页面 | 说明 |
|---|---|---|
| 每日明细 | 一进二 / 二进三 / 三进四明细 | 每只 T-1 首板（二板、三板）在 T 日的竞价、封板、触板、浮盈；含当日首板（次日候选） |
| 天梯 | 涨停天梯、跌停天梯 | 按连板高度 / 连续跌停天数分层，看晋级、炸板、断板、补跌 |
| 情绪 | 情绪监测 | 成交额、涨跌家数、涨跌停、炸板率、高度、晋级率、溢价、亏钱效应、情绪温度；可按日 / 周 / 月看任意区间 |
| 舆情 | 舆情监控 | 盘后快讯打分、涨停原因归类、明日题材预判 |
| 盘中 | 盘中监控 | 9:25 竞价和连续竞价的实时预警（竞价抢筹、板块集体异动、龙头、封板 / 炸板等），高级别弹 macOS 通知 |
| 研究 | 策略回测 | 一进二「弱转强」三个口径、三个基准，参数可在页面上调 |

### 1.2 组成与数据流

```text
同花顺 thsdk / 问财
  ├─ scripts/download.py          日线、证券列表、指数、流通股本
  ├─ scripts/download_limitup.py  问财涨停明细：首次涨停时间、涨停原因、9:25 竞价成交额
  └─ scripts/download_news.py     快讯、涨停分析、热门板块、人气榜、事件日历 → 明日题材预判
        │
        ▼
data/raw/ ── scripts/run_backtest.py ──▶ data/features/（明细、天梯、情绪、回测宽表）+ reports/（回测报告）
        │
        ├─ scripts/daily_update.py    每日编排，launchd 定时运行
        └─ scripts/live_monitor.py    盘中监控，launchd 每个工作日 9:05 启动 → data/live/YYYYMMDD/
        │
        ▼
app/dashboard.py（Streamlit 看板，http://localhost:8501）
```

### 1.3 目录结构

| 路径 | 内容 |
|---|---|
| `app/` | 看板：`dashboard.py` 是入口，`views/` 下每个页面一个脚本 |
| `src/ashare_bt/` | 核心代码：`data` 下载、`features` 特征、`strategy` 选股、`backtest` 回测、`live` 盘中、`monitor.py` 舆情、`themes.py` 题材归类 |
| `scripts/` | 命令行脚本；`scripts/launchd/` 是两个定时任务配置 |
| `config/` | 4 个 yaml 配置（见第 9 节） |
| `data/` | `raw` 原始数据、`features` 特征、`live` 盘中记录、`logs` 日志 |
| `reports/` | 回测报告 `mvp_report.md`、图表、信号明细 |
| `docs/` | 本文档 |
| `tests/` | 单元测试：`uv run pytest` |

## 2. 快速开始

### 2.1 环境

- macOS，项目路径 `/Users/wangjie/ashare-backtest`。
- Python 3.12，用 uv 管理，虚拟环境在 `.venv`；PyPI 走阿里云镜像（见 `pyproject.toml`）。
- 主要依赖：thsdk 2.0.2、pandas 3、streamlit 1.65、altair 6。
- 安装或同步依赖：`uv sync`。

### 2.2 同花顺登录

- thsdk 按以下顺序认证：
  1. 环境变量 `THS_USERNAME` 和 `THS_PASSWORD`（两个都要设）；
  2. 项目根目录的 `account.session`；
  3. 临时账号。
- 目前用的是临时账号，会话保存在项目根目录的 `account.session`（已加入 .gitignore）。不要删除，也不要外传。
- 定时任务没有设置这两个环境变量，靠 `account.session` 登录。
- 同一个账号同时登录会互相挤掉。盘中（9:05～15:00）不要手动运行下载类、问财类脚本；系统自身用锁文件避免冲突（见 3.4）。

### 2.3 启动看板

```bash
cd /Users/wangjie/ashare-backtest
uv run streamlit run app/dashboard.py        # 前台运行，Ctrl+C 停止

# 或者后台运行（关掉终端也不停）：
nohup .venv/bin/streamlit run app/dashboard.py > data/dashboard.log 2>&1 &
```

- 浏览器打开 http://localhost:8501 。只监听本机（`.streamlit/config.toml` 里设了 `address = "localhost"`）。
- 健康检查：`curl -s http://localhost:8501/_stcore/health`，返回 `ok` 即正常。
- 停止或重启：

```bash
pkill -f "streamlit run app/dashboard.py"; sleep 1
nohup .venv/bin/streamlit run app/dashboard.py > data/dashboard.log 2>&1 &
```

- 看板不会开机自启，电脑重启后要手动启动。定时任务和盘中监控不依赖看板，看板关着也照常运行。
- 改了 `app/` 下的文件：保存后，已打开的页面会自动重跑（设置了 `runOnSave = true`）。
- 改了 `src/ashare_bt/` 下的代码：要重启看板。
- 改了 `config/*.yaml`：见第 9 节。

### 2.4 从零准备数据

只在第一次使用或数据损坏时需要；日常由定时任务增量更新。按顺序运行：

```bash
uv run python scripts/download.py                    # 全市场日线等，约 20～30 分钟
uv run python scripts/download_limitup.py            # 问财涨停明细（回测区间全部 T-1 日），约 1 小时；问财限流时更久，中断后重跑会续传
uv run python scripts/run_backtest.py                # 明细、天梯、情绪、回测报告，约 0.5 分钟
uv run python scripts/download_news.py --backfill 10 # 舆情：回填近 11 个交易日，并生成回溯预判
```

- 盘中监控第一次运行时会自动构建板块成分，约 3 分钟。

### 2.5 日常使用建议

| 时段 | 看什么 |
|---|---|
| 盘前（8:50 更新后） | 「舆情监控」明日预判（盘后消息统计到 9:25）；用「涨停天梯」「情绪监测」复盘前一天 |
| 9:15～9:30 | 「一进二明细」切到「按首板日 T-1」看今天的候选；9:25 后看「盘中监控」的竞价视图和一进二信号视图 |
| 盘中 | 「盘中监控」预警流；高级别预警会弹 macOS 通知 |
| 盘后（约 16:15 数据更新完） | 「一进二明细」看 T 日表现；「涨停 / 跌停天梯」「情绪监测」「舆情监控」 |
| 研究 | 「策略回测」调整参数，看封板率和收益如何变化 |

## 3. 每日自动更新

### 3.1 时间线（工作日）

| 时间 | 任务 | 做什么 |
|---|---|---|
| 8:50 | daily_update | 通常只更新舆情（加入隔夜快讯，刷新明日预判）；如果前一天的完整更新失败了，这次会补跑完整更新 |
| 9:05 | live_monitor | 启动盘中监控：9:25 取竞价结果，9:30～15:00 实时预警，15:00:30 收盘后退出 |
| 15:45 | daily_update | 完整更新：日线 → 问财明细 → 回测与每日明细 → 舆情，共约 15～30 分钟（大部分时间花在日线全量重下） |
| 19:30 | daily_update | 当天问财明细没取全就补（收盘后不久问财可能还没更新当天的数据），然后更新舆情 |
| 22:30 | daily_update | 同 19:30 |

- 定时任务按星期几运行，不认节假日。节假日运行时发现没有新交易日，只更新舆情；盘中监控发现不是交易日会自动退出。
- 电脑睡眠时错过的时间点，唤醒后补跑一次；关机时错过的，要等到下一个时间点。
- 每一步的完整输出都写进明细日志（见 3.3）。

### 3.2 daily_update 怎么决定做什么

1. 加锁 `data/.daily_update.lock`。已有一个更新在跑：写「跳过：另一个更新任务正在运行」后退出。
2. 检查冲突：下载、回测脚本正在运行，或者 9:10～15:05 之间盘中监控正在运行，都会跳过本次，避免同一个同花顺账号重复登录。
3. 确定最新交易日：取上证指数日线的最新日期。15:30 之前运行时，最多只认到昨天。取失败时按 30 / 60 / 120 秒重试（刚唤醒时网络可能还没通）；仍失败则写「失败：取最新交易日出错（…）」并发通知。
4. 判断要做什么：
   - 本地数据早于最新交易日（或加了 `--force`）：完整更新。
   - 已是最新，但当天问财明细还没取全（缺首次涨停时间、涨停原因、T-1 竞价额，或缺前一交易日的 T 日竞价额）：只补问财明细，然后重跑回测与明细。
   - 其他情况：只更新舆情（加了 `--no-news` 则什么都不做）。
5. 完整更新的步骤：

| 步骤 | 脚本 | 超时 | 失败重试 |
|---|---|---|---|
| 日线 | `download.py --refresh` | 60 分钟 | 1 次（间隔 2 分钟） |
| 问财明细 | `download_limitup.py`（回查最近 5 个交易日没取全的） | 60 分钟 | 1 次 |
| 回测与每日明细 | `run_backtest.py` | 30 分钟 | 不重试 |
| 舆情 | `download_news.py` | 30 分钟 | 不重试 |

- 前三步中任一步失败：写「失败：…失败（退出码 N），详见 …」并发通知；下次运行会重新来过。
- 舆情失败不影响前面的结果，只写进汇总行。

### 3.3 怎么确认更新成功

汇总日志 `data/logs/daily_update.log`，每运行一次写一行，行首是时间。完整更新成功时，内容形如（以 10-16 为例）：

```text
完成（日线、问财明细、回测与每日明细、舆情，15.2 分钟）：20261016 情绪温度 36（偏冷）、两市成交 1.55 万亿、涨停 63、跌停 10、炸板率 44%、最高 11 板；T日 20261016 晋级 一进二 4/30、二进三 1/2、三进四 1/2；20261016 首板 56、二板 4、三板 1 只（次日候选；首次涨停时间 57/61、涨停原因 57/61）；明日题材预判：医药 60%、消费零售 56%、短剧影视 55%
```

（10-16 当天 16:00 那一行实际写的是「涨停原因 0/61」，原因见第 14 节；16:29 已补齐。）

各段含义：
- 「20261016 情绪温度 …、最高 11 板」：当天的市场情绪概况。
- 「T日 20261016 晋级 一进二 4/30」：以当天为 T 日，一进二候选 30 只中有 4 只封板。
- 「20261016 首板 56、二板 4、三板 1 只（次日候选；…）」：当天新产生的下一交易日候选，以及问财明细取到了多少只。
- 「仍缺 …（下次运行自动补）」：问财明细还没取全，19:30 / 22:30 会自动补。
- 「明日题材预判」：调整后概率最高的 3 个题材。

其他确认方式：
- 明细日志 `data/logs/daily_update_YYYYMMDD.log`：每一步的完整输出，排查问题时看这里。
- macOS 通知：「一进二数据已更新」或「一进二数据更新失败」。跳过和只更新舆情时不发通知。
- 看板各页面默认显示最新交易日，日期对了就说明数据已更新。

### 3.4 锁与冲突

| 锁文件 | 作用 |
|---|---|
| `data/.daily_update.lock` | 同一时间只允许一个 daily_update 运行 |
| `data/.live_monitor.lock` | 同一时间只允许一个实时盘中监控运行；daily_update 在 9:10～15:05 发现它被占用就跳过 |

- 锁文件一直存在（0 字节）是正常的。文件存在不代表任务在运行；进程退出后锁会自动释放。
- 不要同时运行两个问财进程，否则会被限流。

### 3.5 手动运行

```bash
uv run python scripts/daily_update.py --dry-run    # 只打印计划，不执行（仍会登录同花顺探测最新交易日）
uv run python scripts/daily_update.py              # 按需更新，判断逻辑与定时任务相同
uv run python scripts/daily_update.py --force      # 不管是否最新，完整跑一遍
uv run python scripts/daily_update.py --no-news    # 不跑舆情
uv run python scripts/daily_update.py --window 10  # 问财明细回查最近 10 个交易日（默认 5）
uv run python scripts/daily_update.py --notify     # 发 macOS 通知（定时任务带了这个参数）
```

### 3.6 定时任务管理（launchd）

配置在 `scripts/launchd/`，已安装到 `~/Library/LaunchAgents/`：

| 任务 | 时间 | 命令 |
|---|---|---|
| `com.ashare.daily-update` | 周一至周五 8:50、15:45、19:30、22:30 | `.venv/bin/python scripts/daily_update.py --notify` |
| `com.ashare.live-monitor` | 周一至周五 9:05 | `.venv/bin/python scripts/live_monitor.py`；异常退出 60 秒后自动重启 |

```bash
# 安装或更新（改了 plist 后重新执行这三行）
cp scripts/launchd/com.ashare.daily-update.plist ~/Library/LaunchAgents/
launchctl bootout gui/$(id -u)/com.ashare.daily-update 2>/dev/null
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.ashare.daily-update.plist

launchctl kickstart gui/$(id -u)/com.ashare.daily-update   # 立即运行一次
launchctl print gui/$(id -u)/com.ashare.daily-update       # 查看状态

# 停用
launchctl bootout gui/$(id -u)/com.ashare.daily-update && rm ~/Library/LaunchAgents/com.ashare.daily-update.plist
```

- 管理盘中监控时，把 `daily-update` 换成 `live-monitor`。
- launchd 自己的输出写到 `data/logs/launchd.log` 和 `launchd_live.log`，只在脚本崩溃时才有内容。

## 4. 看板通用说明

- 侧边栏共 10 个页面：一进二明细（默认页）、二进三明细、三进四明细、涨停天梯、跌停天梯、情绪监测、舆情监控、盘中监控、策略回测、使用说明。
- 数据刷新：页面按数据文件的修改时间缓存。数据更新后，刷新页面或做任意操作即可看到新数据。除「盘中监控」外，页面不会自动刷新。
- 指标卡：大字是当日值，小字是较前一交易日的变化，小折线是近 20 个交易日。颜色只表示升降（上升红、下降绿），不表示好坏，比如跌停家数增加也显示红色。
- 日期切换（天梯页、舆情页）：「前一日」「后一日」按钮加一个日期框，默认最新交易日；数据更新后会自动跳到新的一天；选到非交易日时显示前一个交易日。
- 页面上选的日期、筛选不会写进网址，分享链接只能打开对应页面。
- 涨跌幅一律红涨绿跌；题材颜色刻意避开红绿（见 6.9）。

## 5. 各页面使用说明

### 5.1 一进二 / 二进三 / 三进四明细

用途：每行是一只 T-1 日首板（二进三页为二板、三进四页为三板）的股票，以及它在 T 日（买入日）的表现。三个页面用法相同。日期的含义见 6.1。

控件：
- 查看方式：
  - 「按 T 日（看一进二表现）」（默认）：选的是买入日，看这些候选当天的竞价和结果。
  - 「按首板日 T-1（含当日首板 = 次日候选）」：选的是成为首板（二板、三板）的那天。包含最新交易日的首板，也就是下一交易日的候选，它们的 T 日显示「待开盘」。
- 日期：可选一天，也可选一段区间（先点开始日，再点结束日）；默认最新一天。
- 「只看 T 日竞价红」：只显示 T 日高开（竞价涨幅 > 0）的股票。全部是次日候选时不可用。

指标卡（随题材筛选变化）：
- 一般情况：显示只数、T日封板（括号里是封板率）、T日触板率、T日收盘浮盈均值（不含费用）。
- 全部是次日候选时改为：当日首板、10:00 前涨停、开盘即涨停（一字 / T字）、2 只以上的题材。

热门题材图例：当日 ≥ 2 只的题材（按只数取前 10 个）各配一种颜色。点小块即按这个题材筛选，点「清除筛选」恢复。

表格列：

| 列 | 含义 |
|---|---|
| T-1日序号 | 当日全部候选按 T-1 首次涨停时间从早到晚的名次，越小越强；时间相同时依次比板型（一字 > T字 > 实体）、T-1 竞价涨幅。行首的色条是主题材颜色 |
| T日序号 | 按 T 日竞价涨幅从高到低的名次；相同时竞价成交额大的在前 |
| T-1日、T日 | 日期，同一年内只显示月-日；次日候选的 T 日为「待开盘」 |
| 代码、名称 | |
| T-1日竞价涨幅 | T-1 开盘价 ÷ 前收盘价 − 1 |
| T-1日竞价成交额、T日竞价成交额 | 9:25 集合竞价成交额，单位万元 |
| T日竞价涨幅 | T 日开盘价 ÷ T-1 收盘价 − 1 |
| T-1日涨停原因 | 同花顺涨停原因，按「+」拆成小块；鼠标悬停在小块上，可以看它归到了哪个大类 |
| 题材 | 主题材（见 6.9） |
| 题材内T-1日序号、题材内T日序号 | k/n：同一天、同一主题材的 n 只中排第 k |
| T日封板、T日触板 | ✓ 表示是；次日候选显示「-」。触板 ✓ 但封板为空，就是 T 日炸板 |
| T日收盘浮盈 | T 日收盘 ÷ T 日开盘 − 1，即 T 日开盘买入、当天收盘的浮盈，不扣费；不是回测里的 T+1 卖出收益 |
| T-1涨停时间 | T-1 首次涨停时间；开盘即涨停记为 09:30:00 |

排序与分组：
- 4 个序号列的表头有「正序 / 倒序」按钮；其他列点列名，在升序（↑）、降序（↓）之间切换。
- 点「题材」列名：按题材分组，只数多的题材在前，组内按题材内 T-1 日序号排列。
- 选了多天时，总是先按日期从新到旧分组，排序只在每天内部生效。

### 5.2 涨停天梯

用途：看一天之内的连板梯队，每层是一个连板高度。

- 日期：「前一日」「后一日」按钮或日期框，一次看一天。
- 7 张指标卡：
  - 涨停；连板（≥ 2 板）；

- 控件：
  - 层内排序：「按涨停时间」（默认）/「按题材」。

  - 选了题材才出现「包含次要题材」。
- 天梯：
  - 一层一个高度，最高板在上、首板在最下面。
  - 层头显示：N 只；晋级 a/b · x%（今天 h 板中昨天是 h−1 板的只数 ÷ 昨天 h−1 板的只数）；炸板、断板、停牌的计数（不显示失败卡片时也有）。

- 卡片：

  - 炸板：昨天 h−1 板，今天触及涨停但没封住；

## 6. 口径与术语

### 6.1 日期命名

这部分最容易误解：

- T-1：股票成为第 n 板（首板、二板、三板）的那天。
- T：买入日，即 T-1 的下一个交易日，而且这只股票当天要有成交（停牌的不算候选）。
- T+1：T 之后这只股票的下一个交易日（停牌则顺延）。
- 一进二：T-1 是首板，看 T 日能不能涨停（成为二板）。二进三、三进四同理。
- 回测的 T 日范围：20241014～20261015，共 487 天。明细页还包括最新一天，以及下一交易日的候选。

### 6.2 股票池

| 用在哪里 | 口径 |
|---|---|
| 明细、天梯、回测、情绪页的涨跌停类指标 | 剔除名称当前含 ST 的股票，以及上市不足 60 个交易日的次新股（按有成交的天数计） |
| 情绪页的涨跌家数、成交额 | 全部 A 股（含 ST、次新股、北交所）；「两市成交额」只算沪深，北交所单列 |
| 盘中监控 | 剔除 ST，含次新股 |

### 6.3 涨跌停与板型

- 涨跌幅限制：主板 10%，创业板、科创板 20%，北交所 30%。按代码区分板块：68 开头为科创板，30 开头为创业板。
- 涨停价 = 前收盘价 × (1 + 涨跌幅限制)：沪深四舍五入到分；北交所涨停价向下截断、跌停价向上取整。
- ST 不单独建模：历史上 ST 期间的涨停（5%）达不到 10% 的涨停价，自然不算涨停。新股上市初期的特殊涨跌幅也没有建模，靠 60 日次新过滤排除。
- 判定（容差半分钱）：
  - 封板：收盘价 = 涨停价；
  - 触板：最高价 = 涨停价；
  - 炸板：触板但收盘没封住。
- 板型：
  - 一字板：最低价也等于涨停价；
  - T字板：开盘涨停，盘中打开，收盘封回；
  - 实体板：其余的封板。
- 跌停对称：一字跌停、倒T字跌停、实体跌停；翘板 = 触及跌停但收盘没封住。
- 和同花顺的涨停事件对比，一致率约 99%（剔除历史 ST 日）。

### 6.4 连板与首板

- 连板数：连续涨停的交易日数，停牌不打断。
- 首板：当天涨停，前一个交易日没涨停。
- 第 n 板（n ≥ 2）：连板数等于 n，并且这串连板是从首板开始数的。
- 天梯的「晋级」：今天 h 板中昨天是 h−1 板的只数 ÷ 昨天 h−1 板的只数。

### 6.5 晋级与收益

- 晋级（封板）：T 日收盘涨停。封板率 = 晋级只数 ÷ 候选只数；触板率 = T 日最高价触及涨停的比例。
- 买入价：T 日开盘价，即 9:25 集合竞价成交价。
- 卖出规则：

| 规则 | 卖出方式 |
|---|---|
| r1 | T+1 开盘卖 |
| r2 | T+1 收盘卖 |
| r3 | T 日封板的 T+1 收盘卖，否则 T+1 开盘卖 |
| r4 | T+1 开盘较 T 日收盘低开超过 3% 的开盘卖，否则 T+1 收盘卖 |

- r1～r4 都扣交易成本（见 6.7）。
- 明细页的「T日收盘浮盈」= T 日收盘 ÷ T 日开盘 − 1，不扣费。

### 6.6 弱转强策略

截面指标（在同一个 T 日、同一板位的全部候选中计算）：

| 指标 | 定义 |
|---|---|
| 强度分位 P_str | 按 T-1 首次涨停时间排名：(名次 − 1) ÷ (有时间的只数 − 1)。0 最强（最早涨停），1 最弱。只有 1 只时取 0.5；没有首次涨停时间的为空 |
| 标准化竞价涨幅 auc_norm | (T 日开盘价 ÷ 前收盘价 − 1) ÷ 涨跌幅限制。例：主板高开 5%，auc_norm = 0.5 |
| 竞价分位 P_auc | 按 auc_norm 从高到低的名次分位，0 是竞价最高 |
| Δ | P_str − P_auc，越大说明「昨天弱、今天竞价强」越明显 |

条件：
- 可交易：T 日不是开盘即涨停（买不进），并且当天候选不少于 8 只。
- 弱板：P_str ≥ 0.5。
- 竞价区间：auc_norm 在 0.2～0.7 之间，约等于主板高开 2%～7%、创业板和科创板高开 4%～14%。

口径：

| 口径 | 条件 |
|---|---|
| 基准1·全部首板次日 | 可交易 |
| 基准2·弱板次日 | 可交易 + 弱板 |
| 基准3·弱板+竞价区间 | 可交易 + 弱板 + 竞价区间 |
| 口径A·分位反转 | 基准3 + P_auc ≤ 0.2 |
| 口径B·超越强板组 | 基准3 + auc_norm 高于当天强板组（P_str ≤ 0.3）auc_norm 的中位数 |
| 口径C·排名跃迁 | 可交易 + 竞价区间 + Δ ≥ 0.4（不要求弱板） |

- 「前2」：口径 A / B / C 每天按 Δ 从大到小最多取 2 只；基准口径不限只数。
- 参数在 `config/settings.yaml` 的 strategy 段；「策略回测」页可以临时调整。
- 样本内：T 日 ≤ 20251231（300 天）；样本外：之后的日期（187 天）。
- 北交所没有首次涨停时间，P_str 为空，所以只会出现在基准1 中。

### 6.7 回测方法

- 组合：当天入选的股票等权买入。因为 T 日买、T+1 卖，资金要占用两天，所以资金分成两份轮流使用；没有信号的日子收益记为 0。
- 交易成本：
  - 佣金 0.025%（买卖双边）；
  - 印花税 0.05%（只在卖出时收）；
  - 过户费 0.001%（双边）；
  - 滑点 0.3%（买卖各一次）。
  - 价格不变时，一买一卖约亏 0.70%。没有计入最低 5 元佣金。
- 指标（一年按 242 个交易日）：累计收益、年化收益、最大回撤、夏普（无风险利率取 0）。
- 盈亏平衡封板率：让单笔期望刚好为 0 的封板率 = −未封板组 r1 均值 ÷ (封板组 r1 均值 − 未封板组 r1 均值)。
- 显著性：用两比例 z 检验（双侧），比较信号组和「对照池中其余样本」的封板率；「提升(百分点)」是两者之差 × 100。封板率的置信区间用 Wilson 95% 区间。
- 无未来函数：选股只读取 T-1 收盘后和 T 日 9:25 能拿到的字段（列名以 key_、x_ 开头）。测试会把结果列打乱，确认选股结果不变。

### 6.8 情绪指标

| 指标 | 定义 |
|---|---|
| 上涨 / 下跌家数 | 收盘价较前收盘价上涨 / 下跌（全部 A 股） |
| 两市成交额 | 沪深成交额，不含北交所 |
| 涨停、跌停、触板家数 | 合格股票池（见 6.2） |
| 炸板率、封板率 | 炸板率 = (触板 − 涨停) ÷ 触板；封板率 = 涨停 ÷ 触板 |
| 连板家数 | 连板数 ≥ 2 的涨停股 |
| 涨停高度、跌停高度 | 最高连板数、最长连续跌停天数 |
| 首板晋级率 | 昨日首板中今天涨停的只数 ÷ 昨日首板数 |
| 连板晋级率 | 昨日连板（≥ 2 板）中今天继续涨停的比例 |
| 昨日 X 溢价 | 昨天是 X（涨停、连板、首板、炸板、跌停）的股票，今天收盘涨幅的等权平均，停牌的不计；「昨日涨停（开盘）」用今天开盘价算 |
| 大面 | 昨天涨停、今天跌停 |
| 天地板 | 盘中触及涨停、收盘跌停 |
| 高位补跌 | 近 20 个交易日内最高 ≥ 3 板，今天跌停 |
| 10点前涨停 | 首次涨停时间不晚于 10:00 的涨停股（2024-10 起才有数据） |

情绪温度：
- 9 个分项：涨停家数、连板家数、涨停高度、封板率、首板晋级率、昨日涨停溢价、上涨占比，以及两个反向指标：跌停家数、大面。
- 每个分项取它在近 250 个交易日中的分位（至少要有 60 天），反向指标取 1 − 分位；9 项等权平均后乘以 100（至少 7 项有值才计算）。
- 档位：低于 20 冰点，20～40 偏冷，40～60 中性，60～80 偏热，80 及以上高潮。
- 从 2024-04-02 起才有值（前 60 天用于预热）。
- 这是相对近一年的位置，不是绝对水平：长期低迷之后，一般的行情也可能显示偏热。

### 6.9 题材归类

- 同花顺的涨停原因形如「AI漫剧+影视院线+北京国资」，按「+」「、」「，」「；」「/」拆成标签。
- 每个标签按 `config/theme_groups.yaml` 从上到下匹配关键词，归到第一个命中的大类（40 个题材类、8 个事件类）；没命中的保留原名。
- 主题材的取法，按优先级：第一个命中的题材类 → 第一个没归类的标签 → 事件类（如业绩、国资、重组）。
- 颜色：当日 ≥ 2 只的题材（按只数前 10 个）各配一种颜色，刻意避开红绿；其余为灰色。同一个题材在不同日期、不同页面可能是不同颜色。
- 想调整归类：编辑 `config/theme_groups.yaml`（更具体的类要放在前面），保存后刷新看板即生效，不用重跑回测。

## 7. 舆情与明日题材预判

### 7.1 数据来源

由 `scripts/download_news.py` 下载，每天 15:45、19:30、22:30、8:50 跟随 daily_update 运行。

| 数据 | 来源 | 说明 |
|---|---|---|
| 7×24 快讯 | 同花顺快讯（含「重要」栏目） | 增量抓取，按 id 去重；2026-09-21 起 |
| 涨停分析 | 同花顺个股涨停分析 | 每只涨停股的行业原因、公司原因 |
| 热门概念 / 行业 | 问财热门板块 | 只能取当前值，只在下一交易日 9:25 前更新，避免混入次日盘中的信息 |
| 人气榜 | 同花顺人气榜前 100 | 同上 |
| 事件日历 | 同花顺热门板块事件日历 | 未来的会议、发布会等事件 |

### 7.2 消息打分

规则在 `config/news_rules.yaml`：
- 盘后窗口：当日 15:00 到下一交易日 9:25。
- 单条快讯：
  - 标题或摘要命中某类关键词，就得到该类的权重：
    - 政策 +3；
    - 涨价供给、技术突破 +2；
    - 海外映射、会议展会、订单合同、重组控制权 +1.5；
    - 回购增持、业绩、研报、传闻大V +1；
    - 利空 −2。
  - 命中多类时，取绝对值最大的那类。
  - 同花顺标为「重要」的 ×1.5；个股公告类 ×0.3。
  - 收评、异动、龙虎榜等复盘类消息不计分。
- 快讯归属题材：按归类表的关键词匹配；另外，快讯关联的个股，按它近 10 个交易日最近一次涨停的主题材计入。
- 消息分：只奖励高于常态的部分（和前 10 个交易日的盘后消息份额比较）；利空直接计入。
- 其他催化：
  - 下一交易日的事件日历，每条 +2（之后 3 天内每条 +1）；
  - 问财热门首次上榜 +1；
  - 人气榜前 100 中每有一只该题材的股票 +0.2。
- 催化分 = 符号 × ln(1 + |合计|)，也就是对数压缩，避免消息多的题材分数过高。

### 7.3 预判模型

- 候选：40 个题材大类，以及当天有涨停的其他题材标签。
- 预测目标：下一交易日该题材涨停 ≥ 3 家（页面上称为「爆发」）。
- 基础概率：逻辑回归，用 7 个量价特征：今日涨停家数、昨日涨停家数、连板家数、市场涨停总数、题材最高板、10:00 前涨停占比、连续活跃天数。每次运行都用全部历史重新训练。
- 调整后概率 = sigmoid(logit(基础概率) + 0.5 × 催化分)。
- 评估：样本外 187 天，2026-10-16 训练的结果。基线是按今日涨停家数（加最高板 ÷ 100）排序。

| 指标 | 模型 | 基线 |
|---|---|---|
| AUC | 0.842 | 0.803 |
| 每日前 3 命中率 | 70.9% | 69.3% |
| 次日最强题材在前 3 的比例 | 51.3% | 50.8% |

### 7.4 怎么看预判

- 基础概率是按历史校准过的。催化权重是经验设定、没有经过回测，所以调整后概率不是严格意义上的概率，主要用于排序。
- 量价模型只比「今天强的明天继续强」好一点；增量主要来自盘后催化，需要结合「关键消息」本身判断。
- 「潜在新题材」是今天没怎么涨、但盘后消息多的题材，适合重点看消息内容。
- 8:50 那次更新会把隔夜消息加进来；开盘前看到的是最终版本。

## 8. 盘中监控

### 8.1 运行流程

| 时间 | 阶段 | 做什么 |
|---|---|---|
| 9:05 | 启动 | 由 launchd 启动。周末、已过 15:00:30、本地已有当日收盘数据时直接退出；板块成分超过 7 天会先重建 |
| 9:15 前、9:15～9:25 | 盘前准备、集合竞价 | 只更新状态 |
| 9:25:05～9:29:50 | 竞价结果 | 约 3 秒一轮取 9:25 竞价数据，来源有三个：问财全市场成交额和价格、实时快照、重点股票逐只的竞价明细。成交额和价格都覆盖 70% 后，计算竞价预警；竞价涨停股再补取封单 |
| 9:30～11:30、13:00～15:00 | 连续竞价 | 全市场快照每 5 秒；板块指数每 15 秒；首次涨停时间每 30 秒；同花顺盘口异动每 60 秒；规则文件每 60 秒重读一次 |
| 15:00:30 | 收盘 | 写最终状态并退出 |

- 重点股票：昨日涨停、炸板、跌停的股票，以及今天的一进二候选。
- 到 9:40 快照仍是上一交易日的数据：判定为非交易日，退出。
- 9:29:30 以后才启动的，当天不监控竞价。

### 8.2 预警规则

阈值在 `config/live_rules.yaml`。「个涨停」= 涨幅 ÷ 涨跌幅限制，例如 0.3 个涨停 = 主板 3%、创业板 6%。

| 类型 | 触发条件 | 级别 | 冷却 |
|---|---|---|---|
| 竞价抢筹 | 竞价成交额 ≥ 1000 万且 ≥ 昨日全天成交额的 5%，竞价涨幅 ≥ 0.2 个涨停，未竞价涨停；按放大比例推前 15 只 | 比例 ≥ 12% 且金额 ≥ 5000 万为高，否则中 | 9:25 一次 |
| 竞价涨停 | 竞价价 = 涨停价（一字候选） | 昨日涨停（连板一字）为高，否则中 | 一次 |
| 核按钮 | 昨日涨停股竞价 ≤ −0.3 个涨停 | ≤ −0.6 为高，否则中 | 一次 |
| 竞价超预期 | 昨日涨停股竞价 ≥ 0.5 个涨停，未涨停 | 中 | 一次 |
| 竞价强势板块 | 竞价 ≥ 0.3 个涨停的成分股 ≥ 3 只；推前 5 个板块 | 中 | 一次 |
| 一进二信号 | 实时口径 A / B / C 出现信号 | 有「前2」时为高 | 一次 |
| 封涨停 | 新封涨停 | 首板低、2 板中、3 板及以上高；当前最强 5 个板块的成分股升一级；板块龙头为高 | 同股 5 分钟 |
| 回封 | 炸板后重新封板 | 2 板及以上或龙头为中，否则低 | 5 分钟 |
| 炸板 | 封住后打开 | 龙头高、连板中、首板低 | 10 分钟 |
| 快速拉升 | 3 分钟内涨 ≥ 0.3 个涨停，且当日成交额 ≥ 3000 万 | 低；昨日涨停股或热门板块成分股升一级 | 10 分钟 |
| 大面 | 昨日涨停、今日跌停 | 中 | 每股每天一次 |
| 板块异动 | 集体：3 分钟内拉升 ≥ 0.2 个涨停或新封板的成分股 ≥ 3 只，且成分股 3 分钟平均涨 ≥ 0.4%。整体：成分 ≥ 10 只的板块 5 分钟平均涨 ≥ 0.8%，且 ≥ 20% 的成分股 5 分钟涨超 0.1 个涨停 | ≥ 5 只且过了 9:40 为高，否则中 | 同板块 15 分钟 |
| 板块跳水 | 阈值为拉升的 1.5 倍，只数多 1 只 | ≥ 5 只或板块内跌停 ≥ 2 只为中，否则低 | 15 分钟 |
| 情绪 | 昨日涨停股平均涨幅 ≤ −2%（亏钱效应扩散）或 ≥ +4%（赚钱效应） | 中 | 各每天一次 |
| 同花顺异动 | 同花顺盘口异动快讯 | 中 | 不重复 |

板块与龙头：
- 板块范围：同花顺概念和行业中，成分 8～400 只的板块；名称含融资融券、沪深股通、昨日、ST 等的非题材板块不算（排除词在 `sector.exclude_keywords`）。
- 9:40 之前波动大：集体异动要求 ≥ 5 只，整体异动阈值翻倍，级别最高到中。
- 同一轮里成分股重合 ≥ 60% 的板块合并成一条预警；同一题材 10 分钟内的第二条板块预警降为低级；60 分钟内首次出现的异动，标题会加「（新启动）」。
- 龙头：每轮取最强的 30 个板块（按涨停数和成分均涨排序）。
  - 空间龙头：封板中板数最高的，并列时取先封板的；
  - 先锋：最早涨停的；
  - 中军：涨幅 ≥ 3% 中成交额最大的；
  - 领涨：涨幅最大的。
  - 只有最强 10 个有涨停的板块，其空间龙头才标「X龙头」。

### 8.3 级别与通知

- 级别分高、中、低三级。只有「高」会弹 macOS 通知（带 Glass 提示音）；20 秒内的多条合并成一条「盘中预警 N 条」。
- 想让中级也弹通知：把 `notify_levels` 改成 `[高, 中]`，盘中 60 秒内生效。
- 所有级别都会写进预警流，可以在「盘中监控」页面查看。

### 8.4 回放与自检

```bash
uv run python scripts/live_monitor.py --replay 20261014            # 用历史分时回放某一天
uv run python scripts/live_monitor.py --replay 20261014 --no-seal  # 回放时不取竞价封单（更快）
uv run python scripts/live_monitor.py --once                       # 取一次实时快照自检
uv run python scripts/live_monitor.py --build-concepts             # 强制刷新板块成分，约 3 分钟
```

- 回放用第一根分时 K 线当作 9:25 竞价，之后逐分钟推进；不发通知。第一次回放某天要下载全市场分时，约 7 分钟。
- 回放只能取到最近约 2 个月的分时；比实时监控少了盘中瞬间触板、5 秒级拉升这类信号。
- 回放某天会覆盖该日已有的记录。不要回放今天，盘中也不要运行回放（会和实时监控抢同一个账号）。

- 板块成分：`data/live/concepts.parquet`（每周自动刷新）；回放用的分时缓存在 `data/live/replay/`。

## 9. 配置文件

| 文件 | 控制什么 | 改完何时生效 |
|---|---|---|
| `config/settings.yaml` | 数据起点、回测区间、样本内截止日、股票池（剔除 ST、次新天数、首板回看、每日最少候选）、策略参数、交易成本 | 下次运行 `run_backtest.py` 时（每天 15:45，或手动运行）。「策略回测」页的默认参数刷新即生效；股票池参数要重跑回测才会体现 |
| `config/live_rules.yaml` | 盘中预警阈值、级别、冷却、通知 | 盘中每 60 秒重读；板块范围（`exclude_keywords`、`min_size`、`max_size`）只在启动时读取 |
| `config/news_rules.yaml` | 消息类别、权重、关键词、来源分类、复盘类标题、题材停用词 | 下次运行 `download_news.py` 时；想立即生效，运行 `uv run python scripts/download_news.py --predict-only` |
| `config/theme_groups.yaml` | 涨停原因 → 题材大类的关键词表，顺序即优先级 | 刷新看板即生效（明细、天梯、舆情）；盘中监控下次启动时生效；预判在下次运行 `download_news.py` 时更新 |

- 修改 yaml 时，金额请写成整数（如 30000000），不要写 3e7：PyYAML 会把这种写法读成字符串。
- 改之前建议先复制一份备份。

## 12. 常见问题

### 12.1 看板打不开

- 先看看看板有没有在运行：`curl -s http://localhost:8501/_stcore/health`。没有返回 `ok` 就按 2.3 重新启动。
- 启动报错时，看 `data/dashboard.log`。

### 12.2 页面提示「未找到…数据，请先运行…」

- 说明对应的数据文件还没生成，按提示运行脚本，或者按 2.4 从零准备数据。

### 12.3 数据没有更新到今天

- 先看 `data/logs/daily_update.log` 最后几行：
  - 「失败：取最新交易日出错（…AuthenticationError…）」：同花顺登录失败，通常是网络还没就绪或会话失效。手动运行一次 `uv run python scripts/daily_update.py`；仍失败的话，检查网络和 `account.session`。
  - 「跳过：…正在运行」：有其他任务在运行，等它结束即可。
  - 「失败：日线 失败…」等：看对应日期的明细日志 `data/logs/daily_update_YYYYMMDD.log`。
- 15:30 之前运行不会把当天算作最新交易日，这是正常的。

### 12.4 明细里缺涨停原因或首次涨停时间

- 收盘后不久，问财可能还没更新当天的数据。19:30、22:30 的定时任务会自动补，汇总行会注明「仍缺…」。
- 也可以手动补（把日期换成要补的 T-1 日）：

```bash
uv run python scripts/download_limitup.py --start 20261016 --end 20261016 && uv run python scripts/run_backtest.py
```

- 北交所没有首次涨停时间，这是数据源本身的限制。

### 12.5 问财限流

- 脚本会自动冷却后重试。不要同时运行两个问财进程；后台补大量数据时加上 `--pause 3`。

### 12.6 盘中监控没有数据，或页面不刷新

- 看监控进程有没有在运行：`pgrep -fl live_monitor`；查看 `data/logs/live_monitor_当天日期.log`。
- 页面在 9:05 之前就打开的，手动刷新一次。
- 手动启动：`launchctl kickstart gui/$(id -u)/com.ashare.live-monitor`。

### 12.7 盘中电脑睡眠

- 睡眠期间监控暂停，唤醒后的第一轮可能集中报出一批「快速拉升」「板块异动」：睡眠期间的涨幅会被当成短时间内的拉升。
- 盘中尽量别让电脑睡眠，可以在终端运行 `caffeinate -i -t 21600`（6 小时内不睡眠）。

### 12.8 题材归类不对

- 编辑 `config/theme_groups.yaml`：给对应的类加关键词，更具体的类放在前面；保存后刷新看板。

### 12.9 改了代码，看板没变化

- `src/ashare_bt/` 下的改动要重启看板（见 2.3）；盘中监控要到下次启动时才生效。

## 13. 已知局限

### 13.1 回测

- 成交假设偏乐观：开盘价既用来算信号，又当成交价。T+1 一字跌停卖不出、成交容量都没有建模。
- 有轻微的前视和幸存者偏差：流通股本用当前快照，ST 按当前名称判断，股票列表只包含当前仍在上市的股票。
- 北交所没有首次涨停时间，A / B / C 实际上不包含北交所。
- 看板上的「封板率最高的口径」、报告里的「样本外最好口径」、分层分析的三分位切点，都是事后挑出来的。
- 结论：弱转强确实能提高封板率（基准1 约 13%，口径A 约 32%），但扣费后所有口径的 r1 均值都为负，「前2」组合累计收益在 −85% 到 −96% 之间。

### 13.2 数据

- 日线的 `--refresh` 是全量重下，每次 15～30 分钟。
- 快讯从 2026-09-21 起才有；更早的日期，舆情类信息会缺失。
- 收盘后不久，问财明细可能还没更新（已有自动补抓，见 3.2）。

### 13.3 盘中监控

- 竞价抢筹覆盖不全：9:25 刚过时，问财可能返回一批值为 0 的竞价成交额，而覆盖率检查把这些也算作已取到，于是停止轮询。这时竞价抢筹实际上只覆盖了重点股票（2026-10-16 就出现了这种情况：只有 78 只有真实成交额）。价格类预警（竞价涨停、核按钮、超预期、强势板块）不受影响。
- 电脑睡眠或网络中断后的第一轮，会集中误报一批拉升类预警（见 12.7）。
- 盘中重启后，已封板的股票会再报一次「封涨停」。
- 回放某天会覆盖该日的实盘记录。
- 锁只覆盖实时模式；daily_update 只在启动时检查一次锁。如果 8:50 的任务拖到 9:05 以后，可能会和盘中监控同时登录。
- 个股题材来自近 60 个交易日的涨停原因，这段时间没涨停过的股票没有题材。
- 「竞价强势板块」的 0.3 个涨停门槛写在代码里，不能在配置文件中修改。

### 13.4 舆情

- 催化权重没有回测；预判复盘只有 13 天，其中 10 天是回溯生成的（回溯日没有热门和人气快照）。
- 长假前的预判，只统计到假期后第一个工作日 9:25 之前的消息；假期中快照也会停更。

### 13.5 看板

- 明细页最多显示 5000 行。
- 题材颜色在每个视图里重新分配，不同日期、不同页面的同一个题材可能颜色不同。
- 情绪温度从 2024-04-02 起才有值。
- 明细表用的 `st.components.v1.html` 已被 Streamlit 标为弃用（日志里会有提示）。升级 Streamlit 之前要先改成 `st.iframe`，否则明细页会无法显示。
